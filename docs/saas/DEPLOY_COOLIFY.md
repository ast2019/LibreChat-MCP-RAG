# استقرار روی Coolify

## پیش‌نیاز

- **سرور:** حداقل ۴ هسته و **۸ گیگابایت RAM** (با مدل داخلی، **۱۲ گیگابایت** پیشنهاد می‌شود). بیلد فرانت‌اند به حدود ۶ گیگابایت حافظه نیاز دارد. اگر RAM کمتری دارید، متغیر `NODE_MAX_OLD_SPACE_SIZE` را کم کنید، یا image را روی سرور دیگری بسازید و فقط اجرا را روی Coolify انجام دهید.
- **دامنه:** یک دامنه مثل `chat.example.com` که رکورد A آن به سرور Coolify اشاره کند.
- **کلید OpenRouter:** از https://openrouter.ai/keys بسازید.

## مراحل

1. **ساخت منبع:** در Coolify گزینه **New Resource → Public/Private Repository** را بزنید و این مخزن را انتخاب کنید. Branch را `main` بگذارید.
2. **Build Pack:** گزینه **Docker Compose** را انتخاب کنید. مسیر فایل `/docker-compose.yml` است.
3. **دامنه:** فقط برای سرویس `api` دامنه بگذارید، **بدون پورت**: `https://chat.example.com`. اپ داخل کانتینر روی پورت ۸۰ گوش می‌دهد و proxy کولیفای به‌طور پیش‌فرض به همین پورت وصل می‌شود. فیلد دامنهٔ سرویس‌های دیگر (`meilisearch`، `rag_api`، `searxng`، `ollama`) را **خالی بگذارید**. کولیفای برای هر سرویس این فیلد را نشان می‌دهد، ولی این‌ها داخلی‌اند و نباید از اینترنت در دسترس باشند.
4. **متغیرها:** در بخش **Environment Variables**:
   - `OPENROUTER_KEY` را وارد کنید. این تنها متغیر اجباری است و تا وارد نشود deploy انجام نمی‌شود.
   - همه `SERVICE_*`ها (رمزها، کلیدهای JWT، `CREDS_KEY`، رمز MongoDB و Meilisearch) را خود Coolify یک بار می‌سازد و نگه می‌دارد.
   - **هشدار:** `SERVICE_HEX_64_CREDSKEY` و `SERVICE_HEX_32_CREDSIV` را بعد از اولین اجرا تغییر ندهید، وگرنه اطلاعات رمزشده قابل خواندن نمی‌ماند.
   - متغیرهای اختیاری مثل `APP_TITLE`، `ALLOW_REGISTRATION` و SMTP در `.env.coolify.example` توضیح داده شده‌اند.
5. **Deploy:** اولین بیلد ۱۰ تا ۲۰ دقیقه طول می‌کشد. وقتی healthcheck سرویس `api` (`/health`) سبز شد، سایت آماده است.
6. **حساب ادمین:** در کولیفای وارد **Terminal** سرویس `api` شوید و این را اجرا کنید:
   ```bash
   cd /app && npm run make-admin -- you@example.com 'YourStrongPassw0rd'
   ```
   اگر حسابی با این ایمیل نباشد، ساخته می‌شود. اگر باشد، رمزش عوض می‌شود و نقش ADMIN می‌گیرد. رمز باید حداقل ۸ کاراکتر باشد. اگر ثبت‌نام عمومی نمی‌خواهید، `ALLOW_REGISTRATION=false` بگذارید.
7. **دادن بسته به کاربران:** طبق [BILLING.md](./BILLING.md).

## HTTPS (لازم)

دامنهٔ سرویس `api` را با `https://` وارد کنید. Coolify خودش گواهی Let's Encrypt می‌گیرد، به شرطی که رکورد DNS به سرور اشاره کند و پورت‌های ۸۰ و ۴۴۳ باز باشند.

- **Passkey فقط روی HTTPS کار می‌کند.** `DOMAIN_CLIENT` و `DOMAIN_SERVER` از همین دامنه ساخته می‌شوند و باید آدرس `https://` باشند. روی `http://` دکمهٔ ورود با کلید عبور، بخش «کلیدهای عبور» در تنظیمات و پیشنهاد افزودن کلید عبور نمایش داده نمی‌شوند. برای بررسی، `https://chat.example.com/api/config` را باز کنید؛ باید `"passkeyLoginEnabled": true` داشته باشد.
- `PASSKEY_RP_ID` اگر خالی باشد از `DOMAIN_CLIENT` گرفته می‌شود. اگر آن را می‌گذارید، فقط نام میزبان را بنویسید (`chat.example.com`)، بدون `https://`، پورت یا مسیر.
- روی `http://` کوکی ورود بدون `Secure` فرستاده می‌شود تا ورود با رفرش صفحه از بین نرود. قبلاً مرورگر کوکی `Secure` را روی http دور می‌انداخت و کاربر با هر رفرش یا تایپ آدرس (مثلاً `/admin`) دوباره رمز می‌خواست. با `SESSION_COOKIE_SECURE=true/false` می‌شود این را دستی تعیین کرد.
- **دامنهٔ نهایی را قبل از ساختن passkeyها مشخص کنید.** هر passkey به نام دامنه گره خورده است. برای جابه‌جایی دامنه، `PASSKEY_RP_ID` را روی نام دامنهٔ قبلی بگذارید، وگرنه کاربرها باید passkey را دوباره بسازند.

## ورود کاربران

- **ایمیل و رمز عبور:** همیشه فعال است. کاربر هنگام ثبت‌نام نام، نام کاربری، ایمیل و رمز وارد می‌کند و با ایمیل و رمز وارد می‌شود.
- **OpenID Connect (اختیاری):** در Coolify این سه متغیر را بگذارید: `OPENID_ISSUER` (مثلاً `https://accounts.google.com` یا آدرس realm در Keycloak)، `OPENID_CLIENT_ID` و `OPENID_CLIENT_SECRET`. آدرس بازگشت `https://chat.example.com/oauth/openid/callback` را در سرویس OpenID ثبت کنید. بعد از redeploy، دکمه ورود زیر فرم ظاهر می‌شود.
  - متن دکمه: `OPENID_BUTTON_LABEL`
  - اگر نمی‌خواهید کاربر جدید از طریق OpenID ساخته شود: `ALLOW_SOCIAL_REGISTRATION=false`
  - `OPENID_SESSION_SECRET` را Coolify خودش می‌سازد.
  - تا این سه متغیر خالی باشند دکمه نمایش داده نمی‌شود. آدرس `/oauth/openid` در این حالت خطای 500 می‌دهد، که رفتار خود LibreChat است.
- **Passkey (اثر انگشت، چهره یا PIN دستگاه):** با `ALLOW_PASSKEY_LOGIN=true` (پیش‌فرض) و دامنهٔ HTTPS فعال است. همهٔ کاربرانی که با ایمیل و رمز ثبت‌نام کرده‌اند (نه فقط مدیرها) می‌توانند کلید عبور بسازند: از کارت «ورود سریع‌تر و امن‌تر با کلید عبور» که بعد از ورود در صفحهٔ گفت‌وگوی جدید می‌آید، یا از **تنظیمات → حساب → کلیدهای عبور** (رمز فعلی را یک بار می‌پرسد). بعد از آن، در صفحهٔ ورود دکمهٔ «ورود با کلید عبور (اثر انگشت / چهره)» را می‌زنند یا کلید عبور را از پیشنهادهای خودکار فیلد ایمیل انتخاب می‌کنند. اگر کاربر «بعداً» را بزند، آن کارت در همان مرورگر دوباره نشان داده نمی‌شود. نام نمایش‌داده‌شده در دستگاه `PASSKEY_RP_NAME` (پیش‌فرض HiveGPT) است.

## ادمین

صفحهٔ چت ادمین **دقیقاً مثل کاربر** است. تنها تفاوت گروه «ادمین» در لیست مدل‌هاست (مدل بدون سانسور). همهٔ ابزارهای مدیریت در یک جا هستند: **منوی حساب → پنل مدیریت** (`/admin`) با چهار بخش:

| بخش | کار |
|---|---|
| داشبورد | فروش، مصرف، سود، نرخ دلار و مدل‌های پرمصرف |
| کاربران و اعتبار | جستجوی کاربر، درصد مصرف، افزودن بسته یا اعتبار |
| دسترسی کاربران | روشن/خاموش کردن امکانات برای همهٔ کاربران: جستجوی وب، پرسش از فایل، ارجاع به فایل، حافظه، چت موقت، نشانک‌ها، پرامپت‌ها، دستیارها، فروشگاه دستیارها، MCP، مهارت‌ها |
| حالت پیشرفته | فقط برای خود ادمین و فقط در همان مرورگر: سازندهٔ دستیار، پرامپت‌ها، MCP، مهارت‌ها و دکمه‌های تنظیمات داخل آن‌ها در صفحهٔ چت ظاهر می‌شوند |

- مقادیر `interface` در `librechat.saas.yaml` با `permissionSync: 'seed'` فقط **یک بار** به نقش USER نوشته می‌شوند (و دوباره فقط وقتی خود yaml عوض شود). تغییرات بخش «دسترسی کاربران» با ری‌استارت از بین نمی‌رود.
- با `adminFullAccess: true` دسترسی‌های نقش ADMIN در هر شروع به پیش‌فرض ADMIN (همه روشن) برمی‌گردد و محدودیت model spec برای ادمین برداشته می‌شود تا دستیارهایی که در حالت پیشرفته می‌سازد کار کنند.

## لیست مدل‌ها

کاربر مدل‌ها را بر اساس برند می‌بیند، با لوگوی هر برند، به این ترتیب: **Claude، ChatGPT، DeepSeek، Gemini، Grok، GLM، Qwen، Perplexity**، بعد «ابزارها» (جستجو و پژوهش، پرسش از فایل‌ها) و «محرمانه». اسم و لوگوی سرویس واسط (OpenRouter) هیچ‌جا نمایش داده نمی‌شود؛ در پیام خطا و برچسب‌ها «HiveGPT» آمده است.

- برای اضافه کردن مدل، یک مورد زیر `modelSpecs.list` با `group` همان برند و `iconURL` (کلید برند مثل `anthropic`، `openai`، `deepseek`، `google`، `xai`، `zhipu`، `qwen`، `perplexity`) بسازید.
- شناسه‌های `~…-latest` همیشه جدیدترین مدل آن برند در OpenRouter را می‌گیرند.

## کیفیت جستجو

- **Reranker برای جستجوی وب (اختیاری، پیشنهادی):** `JINA_API_KEY` (از https://jina.ai/reranker) یا `COHERE_API_KEY` را در Coolify بگذارید. اگر هر دو باشند، Jina استفاده می‌شود. بدون کلید، جستجو بدون reranker کار می‌کند.
- **مدل embedding فایل‌ها:** پیش‌فرض `openai/text-embedding-3-large` با ۱۵۳۶ بُعد است. **قبل از اینکه کاربرها فایل آپلود کنند انتخاب نهایی را بکنید.** بعد از تغییر `EMBEDDINGS_MODEL` یا `EMBEDDINGS_DIMENSIONS`، فایل‌های قبلی باید دوباره آپلود شوند، چون بردارهای دو مدل با هم قابل مقایسه نیستند.

## چت محرمانه و مدل داخلی

- **محرمانه (ZDR):** گروه «محرمانه» در لیست مدل‌ها از endpoint جداگانه `OpenRouterPrivate` استفاده می‌کند. هر درخواست به OpenRouter می‌گوید فقط به providerهای Zero Data Retention برود که داده جمع نمی‌کنند (`provider.zdr: true` و `data_collection: deny`). اگر چنین providerی در دسترس نباشد، درخواست خطا می‌دهد و به مسیر عادی برنمی‌گردد. جستجوی وب و فایل در این چت‌ها خاموش است، چون آن‌ها از مسیرهای غیر ZDR می‌روند.
- **داخلی:** مدل `gemma3:4b` روی کانتینر `ollama` اجرا می‌شود و هیچ داده‌ای از سرور خارج نمی‌شود. این چت‌ها از حافظه هم مستثنا هستند. اولین اجرا مدل را (حدود ۳٫۳ گیگابایت) دانلود می‌کند و از آن مدل `hivegpt-local` را با تعداد رشته و طول متن تنظیم‌شده می‌سازد.

### مدل بدون سانسور (فقط ادمین)

در گروه «ادمین» لیست مدل‌ها دو گزینه هست که فقط کاربرهای ADMIN می‌بینند:

| گزینه | رفتار |
|---|---|
| **بدون سانسور — سریع** | جواب مستقیم، بدون مرحلهٔ فکر |
| **بدون سانسور — برنامه‌نویسی (فکر عمیق)** | اول فکر می‌کند (متن فکر در یک بخش جمع‌شونده دیده می‌شود)، بعد جواب می‌دهد؛ کندتر |

- مدل: `huihui_ai/Qwen3.6-abliterated:35b` (۳۵ میلیارد پارامتر، ۳ میلیارد فعال؛ نسخهٔ abliterated که امتناع‌هایش برداشته شده). کانتینر `ollama` آن را با نام `hivegpt-uncensored` می‌سازد.
- اولین اجرا حدود **۲۳ گیگ** دانلود دارد؛ تا تمام نشود، این گزینه‌ها خطای model not found می‌دهند. هنگام کار حدود **۲۲ گیگ RAM** می‌گیرد، برای همین `LOCAL_MODEL_MEMORY` پیش‌فرض ۳۲g است.
- هر بار فقط یک مدل در حافظه است. رفتن از «داخلی» به «بدون سانسور» یا برعکس، چند ده ثانیه برای بارگذاری طول می‌کشد.
- کاربر عادی این گزینه‌ها را نمی‌بیند. اگر درخواستی را دستکاری کند و نام آن‌ها را بفرستد، سرور با «Invalid model spec» رد می‌کند.
- این چت‌ها مثل «داخلی» از حافظه مستثنا هستند و چیزی از سرور بیرون نمی‌رود.
- برای نصب نکردن: `LOCAL_MODEL_UNCENSORED=none`.

### سرعت مدل داخلی روی ماشین مجازی (ESXi)

Ollama به تعداد vCPUهایی که می‌بیند رشته می‌سازد، حتی اگر کانتینر فقط به چند هسته دسترسی داشته باشد. در نسخهٔ قبل کانتینر ۲ هسته داشت و ۲۴ رشته می‌ساخت؛ نتیجه ۰٫۲ توکن در ثانیه بود. حالا پیش‌فرض‌ها این‌اند:

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `LOCAL_MODEL_CPUS` | 12 | سقف CPU کانتینر |
| `LOCAL_MODEL_THREADS` | 12 | تعداد رشته؛ حداکثر برابر `LOCAL_MODEL_CPUS`، بهتر است برابر هسته‌های فیزیکی باشد |
| `LOCAL_MODEL_CONTEXT` | 8192 | طول متن، هم‌اندازهٔ `tokenConfig` در yaml |
| `LOCAL_MODEL_MEMORY` | 32g | سقف RAM (مدل بدون سانسور ~۲۲ گیگ می‌خواهد) |
| `LOCAL_MODEL_UNCENSORED` | `huihui_ai/Qwen3.6-abliterated:35b` | مدل بدون سانسور ادمین؛ `none` = نصب نشود |
| `LOCAL_MODEL_UNCENSORED_CONTEXT` | 16384 | طول متن مدل بدون سانسور |

تنظیمات ماشین مجازی در ESXi (Edit settings → CPU):
- **Cores per Socket** را برابر کل vCPUها بگذارید (مثلاً ۲۴ هسته در ۱ سوکت) به جای ۲۴ سوکت ۱ هسته‌ای.
- داخل اوبونتو `grep -c avx2 /proc/cpuinfo` باید بیشتر از صفر باشد. اگر صفر است، AVX2 به VM نمی‌رسد و مدل چند برابر کند می‌شود. VM را خاموش کنید، **Compatibility** را به آخرین نسخهٔ ESXi ارتقا دهید، و اگر vCenter دارید، EVC را خاموش کنید یا روی نسلی بگذارید که AVX2 دارد.
- Ryzen 9 3900 دوازده هستهٔ فیزیکی دارد. ۲۴ vCPU یعنی همهٔ رشته‌های میزبان. برای مدل بیشتر از ۱۲ رشته نگذارید، چون دو رشتهٔ یک هسته با هم سریع‌تر نمی‌شوند و بقیهٔ سرویس‌ها هم CPU لازم دارند.
- **حافظه:** مدل حافظه (`google/gemini-3.8-flash`) برای همه چت‌ها روی همان مسیر ZDR اجرا می‌شود و هزینه‌اش از اعتبار کاربر کم می‌شود.

## چرا این‌قدر سرویس؟

| سرویس | برای چه | اگر حذف شود |
|---|---|---|
| `api` | خود اپ | — |
| `mongodb` | کاربرها، چت‌ها، اعتبار | — (ضروری) |
| `meilisearch` | جستجو در تاریخچهٔ چت‌ها | جستجوی چت‌ها کار نمی‌کند |
| `vectordb` + `rag_api` | پرسش از فایل‌ها | آپلود فایل برای جستجو کار نمی‌کند |
| `searxng` | جستجوی وب | جستجوی وب کار نمی‌کند |
| `ollama` | مدل داخلی | گزینهٔ «داخلی» کار نمی‌کند |

## سرویس‌ها

| سرویس | نقش | Volume |
|---|---|---|
| `api` | اپ اصلی (بیلد از `Dockerfile.multi` با target `api-build`) | `uploads`، `images`، `logs`، `librechat-data` |
| `mongodb` | پایگاه داده اصلی (با احراز هویت) | `mongodb-data` |
| `meilisearch` | جستجو در گفتگوها | `meili-data` |
| `vectordb` + `rag_api` | پرسش از فایل‌ها (RAG). embedding از OpenRouter با `openai/text-embedding-3-large` (۱۵۳۶ بُعد) | `pgvector-data`، `rag-uploads` |
| `searxng` | موتور جستجوی وب خصوصی، فقط داخلی | — |
| `ollama` | مدل داخلی `gemma3:4b` (به نام `hivegpt-local`) برای چت «داخلی (کاملاً محرمانه)». حدود ۴ تا ۵ گیگابایت RAM هنگام استفاده؛ بعد از ۳۰ دقیقه بی‌کاری از حافظه خارج می‌شود | `ollama-models` |

**بکاپ:** در Coolify بخش **Persistent Storage** بکاپ volume `mongodb-data` را فعال کنید. موجودی و تراکنش‌های کاربران آنجاست.

## فایل‌ها و OCR

- **Tesseract** (فارسی و انگلیسی) داخل image `api` نصب می‌شود: بستهٔ `tesseract-ocr` از Alpine و مدل‌های `fas` و `eng` از `tessdata_fast` (نسخهٔ ثابت با بررسی checksum، حدود ۴٫۵ مگابایت). Alpine بستهٔ دادهٔ فارسی ندارد. برای بررسی: `docker compose exec api tesseract --list-langs`.
- **سقف آپلود** در `fileConfig` فایل `config/librechat.saas.yaml`: هر فایل ۵۰ مگابایت، حداکثر ۱۰ فایل و مجموعاً ۱۰۰ مگابایت در هر پیام، آواتار ۲ مگابایت.
- پروکسی Traefik در Coolify به‌طور پیش‌فرض سقفی برای حجم درخواست ندارد و این repo هم سقفی برایش تعیین نمی‌کند. اگر جلوی سرور پروکسی دیگری (مثلاً Cloudflare با سقف ۱۰۰ مگابایت در پلن رایگان، یا nginx) هست، سقف آن را دست‌کم ۵۰ مگابایت بگذارید.
- برای PDF، OpenRouter فقط موتور `native` را به کار می‌برد (`addParams.plugins` در هر دو endpoint OpenRouter). یعنی OpenRouter دیگر PDF را با `mistral-ocr` پولی (به حساب ما و بدون ZDR) نمی‌خواند. PDF مدل‌هایی که ورودی فایل ندارند از OCR خود سرور می‌گذرد.

## تغییر تنظیمات

- **مدل‌ها، ضریب قیمت، بسته‌ها و متن‌های UI** در `config/librechat.saas.yaml` هستند. فایل را ویرایش کنید و commit کنید (از طریق PR). Coolify با webhook دوباره deploy می‌کند.
- برای استفاده از کانفیگ بیرونی بدون rebuild، `CONFIG_PATH` را در Coolify روی یک URL با `https` بگذارید. LibreChat کانفیگ را از URL هم می‌خواند.

## اجرای محلی همین stack

```bash
cp .env.coolify.example .env    # مقادیر را پر کنید (دستور openssl کنار هر کلید آمده)
docker compose up -d --build
# http://localhost
```

## عیب‌یابی

| مشکل | علت محتمل |
|---|---|
| بیلد با `JavaScript heap out of memory` شکست می‌خورد | RAM کم است. `NODE_MAX_OLD_SPACE_SIZE` را کم کنید یا RAM اضافه کنید |
| `No Available Server` | `api` هنوز healthy نشده (اولین بیلد طول می‌کشد)، یا دامنه روی سرویس اشتباهی گذاشته شده است |
| جستجوی وب نتیجه ندارد | لاگ `searxng` را ببینید. بعضی موتورها از IP دیتاسنتر CAPTCHA می‌گیرند؛ لیست موتورها در `deploy/searxng/settings.yml` و `webSearch.searxngSearchOptions.engines` است |
| آپلود فایل برای پرسش کار نمی‌کند | لاگ `rag_api` را ببینید. اعتبار OpenRouter و مدل embedding را بررسی کنید |
| با هر رفرش دوباره رمز می‌خواهد | دامنه را `https://` کنید. اگر `SESSION_COOKIE_SECURE=true` روی دامنهٔ http گذاشته‌اید، آن را خالی کنید |
| دکمهٔ passkey نیست | دامنه HTTPS نیست (`/api/config` مقدار `passkeyLoginEnabled: false` دارد)، `ALLOW_PASSKEY_LOGIN` خاموش است، یا مرورگر از کلید عبور پشتیبانی نمی‌کند |
| مدل داخلی خیلی کند است | در لاگ `ollama` عدد `n_threads` را ببینید؛ باید برابر `LOCAL_MODEL_THREADS` باشد. بخش ESXi بالا را ببینید |
| «داخلی» خطای model not found می‌دهد | دانلود و ساخت `hivegpt-local` هنوز تمام نشده؛ لاگ `ollama` را ببینید |
| قیمت‌ها با نرخ ثابت نشان داده می‌شوند | سرور به `call1.tgju.org` دسترسی ندارد؛ لاگ `api` را برای `[currency]` ببینید |
